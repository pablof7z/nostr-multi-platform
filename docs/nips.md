# NIP Support Matrix

> **Reviewed:** 2026-06-28. This is the v1 pre-release truth source for NMP's
> NIP support claims, audited from `origin/master` at `f38ef8c`. It is a durable
> support matrix, not a tactical roadmap. Active work remains in GitHub Issues.

Do not infer support from a crate name alone: a row is only "supported" when
the current code, tests, docs, or live issues prove the specific
read/write/sign/decrypt surface.

Status meanings:

- **supported**: v1 code exists with platform proof and bounded caveats.
- **partial**: one or more surfaces exist, but platform, product, or runtime
  coverage is intentionally narrower than the NIP.
- **experimental**: reusable mechanics exist, but apps must opt in and own more
  policy before treating it as stable v1 DX.
- **blocked**: implementation cannot be claimed until the linked blocker lands.
- **post-v1**: explicitly deferred in GitHub Issues or release manifests.

Browser private-message and signer details are intentionally summarized here.
The browser signer/private-flow capability model is single-sourced in
[`docs/wasm-surface.md`](wasm-surface.md#browser-signerprivate-flow-capability-model);
[#2255](https://github.com/pablof7z/nostr-multi-platform/issues/2255) records
the detailed browser guide acceptance trail. Migration steps for downstream apps
belong to [#2254](https://github.com/pablof7z/nostr-multi-platform/issues/2254).
