# ADR-0055 Rung 3 — Producer omits Unchanged; NMP-owned rev-aware host apply (the payoff rung)

- **Status:** Proposed (2026-06-14). Implementation plan + design addendum to
  [`0055-incremental-projection-emission.md`](0055-incremental-projection-emission.md)
  and [`0055-pr-ladder.md`](0055-pr-ladder.md).
- **Parent decisions this rung executes:** D1 (per-projection rev is the unit of
  change), D3 (self-healing via carried rev; absence == Unchanged, never Cleared),
  D4 (epoch/session re-baseline), D6 (drain semantics), D7 (rev-aware host apply).
- **Landed prerequisites:** Rung 0 (#1365 instrumentation + S6 harness), Rung 1
  (#1376 manifest + completeness oracle), Rung 2 (#1385 wire contract carries
  `projection_rev` + `state` + `snapshot_epoch` + `session_id`). Master @
  `5b58c700b`.
- **Codex review:** two `codex exec` passes (gpt-5.5, xhigh) pressure-tested the
  omit-row contract, native rebaseline correctness, and the
  rev-aware-apply-in-generated-code approach. Verdict + the changes it forced are
  recorded in [§7](#7-codex-review--what-changed). The single load-bearing change:
  **decode-before-commit + a sticky `needsResync` latch is the sufficient Rung-3
  self-healing floor under synchronous in-process delivery — no per-frame full
  manifest is needed in Rung 3** (that, and the resync FFI, are Rung 4).

---

## 1. The goal restated precisely

Rung 2 made the wire *signal* unchanged-ness; it still serializes every
projection's payload every tick (the S6 harness measured **81.2 % projection
serialization waste**). Rung 3 turns the signal into savings:

1. **Producer omit-Unchanged.** A Tier-2 built-in whose manifest presence is
   `Unchanged` is dropped from the frame entirely — *no row, not an empty
   payload* (per ADR-0055 D3 "omission == Unchanged", confirmed by codex Q1).
   `Cleared` projections emit an explicit payload-less `Cleared` row. `Changed`
   projections emit the full row.
2. **NMP-owned rev-aware host apply.** A generated/runtime cache-merge layer —
   shipped inside the NMP runtime binding, NOT reimplemented per app — keeps a
   persistent `key → (rev, raw payload bytes)` cache. On each frame it merges
   (`Changed` overwrites, `Cleared` drops, omitted/`Unchanged` retained) and
   re-feeds the existing per-key typed decoders against the *merged full envelope
   set*. App accessors (`model.wallet`, …) are byte-identical to today and app
   code is unchanged. This is the crux; it is what makes incremental-apply
   impossible for an app dev to get wrong.
3. **Encoder buffer reuse** across the 4 Hz ticks on the single actor thread.
4. **Rebaseline semantics.** The host treats a `session_id` or `snapshot_epoch`
   change as a mandatory full cache reset; the kernel guarantees the first frame
   after epoch-bump / session-start is a full baseline.
5. **Empirical acceptance gate.** Re-run S6: the Tier-2 waste ratio must collapse
   from ~81 % to ~0 %. Pass/fail is the measurement, not "looks right."

## 2. How a projection flows today (kernel → wire → native → accessor)

Tracing the exact path so the Rung-3 seam is unambiguous:

```
KERNEL  (actor thread, ≤4 Hz)
  make_update()                              crates/nmp-core/src/kernel/update.rs:226
    run_typed_projections()                  Tier-1 host sidecars
    merge_builtin_typed_projections()        Tier-2 kernel built-in sidecars
    reconcile_diagnostics_fingerprint()      F5 broad diagnostics stamp
    projection_manifest()                     build per-key {rev,presence}  (Rung 1)
    rung2_stamp::stamp_typed_projections()   stamp rev + state onto each row (Rung 2)
    encode_snapshot_with_envelope()          serialize ALL rows               <-- Rung 3 changes here
    record_emitted_for_manifest()            advance last_emitted baseline    <-- Rung 3 reads here
WIRE   nmp.transport.UpdateFrame  { SnapshotFrame { typed_projections:[{key,payload,projection_rev,state}], snapshot_epoch, session_id, tier3... } }
iOS    KernelHandle.decodeFlatBuffer()       KernelBridge.swift:677
         KernelUpdateFrameDecoder.decode()   -> extractTypedProjections() -> [TypedProjectionEnvelope]   (DROPS rev+state today)
         TypedXDecoder.decode(from: envelopes)  envelopes.first{key&&schemaId} -> nil-on-absence  <-- BUG under omission
         -> KernelUpdateResult                 KernelUpdateTypes.swift
       KernelModel.apply(result:)            KernelModel.swift:727  (re-assigns EVERY @Published slot every tick)
ANDROID KernelUpdateFrameDecoder.decode()    android/.../KernelUpdateFrameDecoder.kt
         extractTypedProjections() -> [TypedProjectionEnvelope]  (DROPS rev+state today)
         decodeProjections() -> SnapshotProjections             (rebuilt fully every tick)
       KernelModel.decodeUpdate() -> _state.value = decoded     android/.../KernelModel.kt:149
GALLERY  NmpUpdateFrameDecoder.decodeSnapshot()  calls the Rust gallery helper
         to decode the typed UpdateFrame into the gallery JSON model — see §6.
```

Two facts decide the design:

- **The Swift/Kotlin `TypedProjectionEnvelope` structs drop `projection_rev` and
  `state` today.** They must carry them (Rung 3) for the cache-merge layer to
  function. The Android `TypedProjection` FlatBuffers binding already exposes
  `projectionRev` / `state` accessors (Rung 2 regenerated it); the Swift
  generated binding does too. Only the *hand* envelope structs need the fields.
- **`TypedXDecoder.decode(from:)` returns `nil` when its key is absent, and the
  app maps `nil → empty`.** Under omission that is a silent data-loss bug. The
  cache-merge layer interposes *before* these decoders so they only ever see a
  fully-reconstituted envelope set — they keep their exact current behavior and
  are not regenerated for content, only for the envelope field additions.

## 3. Design decisions

### D3-1. Omit the whole row for Unchanged (not an empty marker row)

Confirmed against ADR-0055 D3 and codex Q1. An empty-payload marker row buys no
robustness — a non-rev-aware reader maps both "absent" and "present-but-empty" to
the empty default — while still paying per-key vtable + offset bytes every tick.
The full byte win requires dropping the row.

`Cleared` is the sole exception: it is emitted as an explicit payload-less row
(`state = Cleared`, no `TypedPayload`) so the host *drops* its cached value. This
preserves the D3 invariant that **absence == Unchanged and is never conflated
with Cleared.** The encoder MUST never emit a `Cleared` row and then also omit it;
exactly one `Cleared` row is emitted on the non-empty→empty transition (the
drain/`note_drain_emit` state machine already produces this — Rung 3 just stops
suppressing it).

### D3-2. Omission is a protocol mode gated on host rev-aware support — NOT graceful degradation

Codex Q1's bound, adapted to NMP's hard-break policy (downstream pins by git rev;
we hard-break and upgrade *all* callers in one PR — no compat shims). There is no
"old NMP host" after the cut. During the staged rollout, two readers kept full
rows:

1. **A host that has not yet shipped the cache-merge layer** within the migration
   PR sequence (Android/desktop land after iOS).
2. **The gallery's former generic `payload:Value` path** (§6), which has now been
   removed in favor of a Rust typed-frame decoder.

Enablement rides the existing host-declaration seam (ADR-0053
`declare_consumed_projections` / `SnapshotRegistry`): a host calls a new
`nmp_app_declare_incremental_apply()` (or sets a flag on the existing chirp
declare call) to advertise that its runtime owns the cache-merge layer. **Until a
host advertises it, the kernel emits full rows for that kernel instance.** This is
not a compat alias — it is a per-instance capability the host *must* set, checked
once at declare time, and it is deleted as a no-op only when every NMP host
advertises it unconditionally (a future cleanup once Tier-1 gating + Rung 4 land).
The flag lives on the kernel's snapshot registry next to the declared-interest
set, single-writer, set before `start`.

> Rationale for keeping the gate even under hard-break: the gate is the
> *mechanism* that makes "first frame for this host is a full baseline" (D4 /
> codex Q2) enforceable per-attach, and it is the seam Rung 5 (ADR-0053 compose)
> already needs. It is durable architecture, not a migration shim.

### D3-3. The NMP-owned rev-aware apply layer: a generated cache-merge interposer

**Where it lives:** a new NMP-runtime module on each platform, generated by
`nmp-codegen` from the same projection registry that already generates the typed
decoders, so it can never drift from the decoder set:

- iOS: `ios/Chirp/Chirp/Bridge/Generated/ProjectionCache.generated.swift`
  (a `ProjectionMergeCache` actor-isolated value type) +
  the `KernelUpdateFrameDecoder` change to carry `rev`/`state` on
  `TypedProjectionEnvelope`.
- Android: `android/app/src/main/java/org/nmp/android/ProjectionCache.kt`
  (generated) + the `extractTypedProjections` change to carry `projectionRev`/`state`.

**What it does (the same algorithm on both platforms):**

```
state: { cache: Map<key, (rev, schemaId, schemaVersion, fileIdentifier, payloadBytes)>,
         appliedSession: u64, appliedEpoch: u64, needsResync: bool, baselined: bool }

merge(frame):
  if frame.session_id != appliedSession || frame.snapshot_epoch != appliedEpoch:
      cache.clear(); appliedSession = frame.session_id; appliedEpoch = frame.snapshot_epoch
      baselined = false; needsResync = false                 # D4 mandatory reset
  for row in frame.typed_projections:
      switch row.state:
        Changed:
          if row.rev <= cache[row.key].rev:  continue        # D3 reorder guard (in-process: never trips, belt+braces)
          # DECODE-BEFORE-COMMIT (codex Q1/Q2): the per-key typed decoder is run
          # on row.payload into a temp; only on success do we overwrite cache and
          # advance rev. On failure: keep prior cache entry, do NOT advance rev,
          # set needsResync = true (do NOT map to empty).
          if typedDecoder(row.key).decodes(row.payload):  cache[row.key] = (row.rev, ...bytes...)
          else:                                            needsResync = true
        Cleared:
          cache.remove(row.key)                              # explicit drop
        # Unchanged is never on the wire (absence). Omitted keys: untouched -> retained.
  baselined = true
  # Re-feed the EXISTING per-key decoders against the merged full envelope set:
  mergedEnvelopes = cache.values()  (+ pass-through Tier-1 always-Changed rows verbatim)
  return KernelUpdateResult(decode each via the unchanged TypedXDecoder.decode(from: mergedEnvelopes))
```

**Why this shape (codex Q3 — chosen over Tantalus per-field delta-apply):**

- The merged envelope set is *exactly* the shape the existing decoders already
  understand. App accessors and `apply(result:)` are unchanged ⇒ zero app
  regression surface, zero per-app correctness re-implementation.
- Absence semantics are centralized in one generated file per platform ⇒ an app
  dev cannot get incremental-apply wrong: they never see the delta mechanics.
- Tantalus-style generated per-field `@Observable` slot updaters are *faster and
  more reactive* but add native state surface and generated switch logic that can
  drift from Rust semantics. Deferred to a later rung (it composes with D7's
  per-projection `@Observable` host-apply win and can be layered on top of the
  cache without changing the wire). For a first iteration that **must not regress
  correctness**, the cache-merge interposer is the SOTA-correct choice.

**The host-apply win (D7) within the cache-merge layer:** the layer additionally
exposes, per frame, the set of keys whose rev actually advanced. `apply(result:)`
re-assigns *only those slots* instead of every `@Published` slot every tick. This
is the SwiftUI/Compose broad-invalidation kill. (The full per-projection
`@Observable` migration — one `ObservationRegistrar` slot per projection — is
noted as a follow-on; Rung 3 delivers the producer-side byte win + the
"assign-only-changed-slots" win, which is the measurable D7 floor.)

### D3-4. Decode-before-commit + sticky `needsResync` IS the Rung-3 self-healing floor

This is the change codex's review forced (Q1/Q2), and it materially simplifies
Rung 3 vs the parent ADR's implied per-frame manifest:

- The kernel→host channel is a **synchronous in-process C callback** on the actor
  thread (`nmp_app_set_update_callback`, quiescing setter — KernelBridge.swift,
  Android JNI push). There is **no in-transit loss and no reordering**. The only
  realistic way a `Changed` row fails to land is a host-side typed-decode failure.
- Therefore: host advances per-key `applied_rev` **only after** a successful typed
  decode + cache commit. On decode failure it keeps the prior cache, does not
  advance rev, and latches `needsResync`. The frame is otherwise applied (other
  keys commit). This preserves *no-silent-corruption*.
- The producer gates with `last_emitted_revs` (emit iff `rev > last_emitted`,
  then `last_emitted = rev`), so it will not re-emit a key it believes it already
  delivered. After a terminal decode failure the host is **known-degraded** for
  that key until the next genuine rev bump (which re-emits it) OR a full baseline.
  Rung 3 surfaces `needsResync` (logs + a diagnostic flag); **Rung 4 drains it**
  via `nmp_app_request_full_snapshot()` (bump epoch → full baseline). A periodic
  baseline is explicitly NOT added — it would re-introduce O(total) cost on a
  cadence and there is no in-process loss to recover from.
- **No per-frame full manifest in Rung 3.** Codex Q2: under this delivery model a
  manifest would only re-discover a gap the host already knows from its own decode
  error; it is a diagnostic guard, not the correctness floor — and the four
  invariants that make it unnecessary (full-replacement Changed rows; rev advances
  only after commit; baseline resets atomically; producer rev discipline tested)
  are all already true / are Rung-3 acceptance criteria.

**The four invariants Rung 3 must hold (all testable):**

1. `Changed` payload is a full replacement of that projection (true — projections
   are state, not patches; ADR-0055 "ship state not ops").
2. Host advances `applied_rev[key]` only after successful typed decode + commit.
3. `session_id`/`epoch` change clears cache + resets `needsResync` + sets
   `baselined = false`, atomically, before any row is merged.
4. Producer rev discipline: semantic change ⇒ rev advances; an emitted row ⇒
   `last_emitted = rev`. (The Rung-1 biconditional oracle already proves the
   first half; Rung 3 adds the omission-aware half.)

### D3-5. Mid-stream attach + the baseline gate (codex Q2)

The host cache starts `baselined = false`. Two protections:

- The kernel guarantees the **first frame after a host advertises incremental
  apply (or after epoch/session change) is a full baseline** — every live Tier-2
  projection `Changed` regardless of rev, every absent-but-known one `Cleared`.
  Implementation: advertising incremental apply (or any epoch bump) clears the
  kernel's `last_emitted_revs`, so the next `make_update` emits all live keys.
- `session_id == 0` (an aux/legacy producer that never stamped it — e.g. the
  `encode_snapshot_frame` pre-flight `running=false` frame, actor/mod.rs:1492)
  is treated by the host as "no incremental contract" → the host does not trust
  omission on that frame (it is a full frame anyway in that path). The host
  exposes merged state to the UI only once `baselined == true`.

### D3-6. Buffer reuse (codex Q3): safe, one trap

Reuse a single `FlatBufferBuilder` across ticks on the actor thread via
`builder.reset()` after `finished_data().to_vec()`. Frame bytes are copied out
(`to_vec`) before the next tick, so the builder buffer is free to reuse. **The one
trap:** never let the host/FFI retain a pointer/slice/offset into the builder
buffer past the callback return — own/copy bytes before `reset()`, treat
FlatBuffer offsets as builder-local. (The current FFI already copies into the
callback's `Data`/`ByteArray`; this is preserved.) Hold the builder in a
kernel-owned field (single-writer actor thread), not a `thread_local`, so its
lifetime is explicit and `Reset` drops it. Per-projection payload buffers
(`builder.create_vector(&entry.payload)`) are already borrow-then-copy; no change.

### D3-7. Tier-1 host projections stay always-Changed in Rung 3 (defensible boundary)

Codex Q4: leaving Tier-1 (feed, follow_list, wallet, dm_inbox, marmot, zaps, …)
ungated is a valid rung boundary, **not** a correctness hazard, *iff the invariant
is strict*: an unregistered Tier-1 projection is emitted (`Changed`) whenever it
is live and explicitly `Cleared` when it goes absent — never silently omitted
(the host cache-merge would otherwise retain a stale Tier-1 value forever). The
cache-merge layer therefore treats a Tier-1 key (no manifest entry, default
`state = Changed`) as always-overwrite, exactly as today. Tier-1 rev registration
is a follow-on rung (and the feed graduates to row-deltas only per D8/Rung 6).

**Metric honesty (codex Q4):** the S6 acceptance gate measures **Tier-2 /
claimed_profiles churn waste** dropping to ~0. We do NOT claim whole-frame /
product waste is zero while the feed remains always-`Changed`. The S6 report
notes line is updated to say "Tier-2 waste_ratio → ~0; Tier-1 (feed) gating is a
later rung."

## 4. Sub-step ladder (Sonnet-codeable, each with its own gate)

Each sub-step is independently reviewable, keeps the build green, and respects the
300-warn/500-hard file-size gate (see §5). Rust producer first, then iOS host,
then Android host; the capstone S6 measurement gates the rung.

### R3-S1 — Producer: omit Unchanged, keep Cleared, gate on host capability
**Crate:** `nmp-core`.
- Add `incremental_apply_enabled: bool` to the snapshot registry (next to the
  ADR-0053 declared set), set via a new `declare_incremental_apply()` on
  `AppHost` + a `nmp_app_declare_incremental_apply()` FFI (nmp-ffi).
- Add `last_emitted_revs: HashMap<&'static str,u64>` to `ProjectionRevTracker`
  (or reuse the existing `last_emitted` — it already tracks per-key emitted rev).
  Add an `omit_unchanged(typed, manifest, enabled) -> Vec<TypedProjectionData>`
  pure transform in **`update/rung3_omit.rs`** (new sibling, mirrors
  `rung2_stamp.rs`): when `enabled`, drop rows whose presence is `Unchanged`;
  keep `Cleared` rows but strip their payload to empty; keep `Changed` rows.
  When `!enabled`, return `typed` unchanged (full rows).
- Clear `last_emitted_revs` on `declare_incremental_apply()` and on `bump_epoch()`
  so the next frame is a full baseline (D3-5).
- Wire it into `make_update` between `stamp_typed_projections` and
  `encode_snapshot_with_envelope`. **`update.rs` is at 499 LOC — the wiring must be
  one call into `rung3_omit`; no net line growth (see §5 extraction).**
- **Gate (`-p nmp-core`):** unit tests in `rung3_omit` — enabled+Unchanged ⇒
  omitted; enabled+Cleared ⇒ payload-less row present; enabled+Changed ⇒ full row;
  `!enabled` ⇒ all rows present; first frame after `declare_incremental_apply` ⇒
  all live keys present (baseline); first frame after `bump_epoch` ⇒ baseline.
  Extend the Rung-1 biconditional oracle to the omission case: "omitted ⟺
  cache-unit unchanged since last emit."

### R3-S2 — Producer: encoder buffer reuse
**Crate:** `nmp-core`.
- Hold a `FlatBufferBuilder<'static>` in a kernel field; `reset()` it at the top
  of each encode instead of `FlatBufferBuilder::new()`. Apply in
  `tier3_frame::encode_snapshot_with_envelope` (and the aux
  `encode_snapshot_frame`). Copy out via `to_vec` before next reset (D3-6 trap).
- **Gate (`-p nmp-core`):** existing round-trip/decode tests stay green; a new
  test drives 100 sequential `make_update` ticks and asserts each returned frame
  decodes independently (no aliasing). Optional: assert zero builder reallocation
  after warmup via capacity check.

### R3-S3 — iOS: carry rev+state on the envelope; generated ProjectionCache; rev-aware apply
**Crate:** `ios/Chirp`. Codegen: `nmp-codegen` (Swift cache generator).
- Add `projectionRev: UInt64` + `state: WireProjectionState` to
  `TypedProjectionEnvelope` (KernelUpdateFrameDecoder.swift); populate from
  `projection.projectionRev` / `projection.state` (the FlatBuffers reader already
  exposes them post-Rung-2).
- Generate `ProjectionCache.generated.swift` from the projection registry
  (`nmp-codegen gen projection-cache --platform swift`). It implements the D3-3
  merge + decode-before-commit (D3-4) and returns the merged envelope set + the
  changed-key set.
- `KernelHandle.decodeFlatBuffer` calls the cache-merge before running the
  `TypedXDecoder.decode(from:)` family (now fed the merged set). On
  session/epoch change the cache resets (D4). `needsResync` is surfaced on
  `KernelUpdateResult` (logged in Rung 3; consumed in Rung 4).
- `KernelModel.apply(result:)` assigns only the slots whose key is in the
  changed-key set (D7 win). Slots not in the set keep their prior value (the
  cache already retained the decoded bytes; the accessor is unchanged).
  `resetAndRestart()` already clears slots; it additionally resets the cache.
- **Gate (Chirp unit tests):** new `ProjectionCacheTests` — omitted key retains
  prior value; Cleared drops; Changed overwrites; reorder guard; session/epoch
  reset re-baselines; decode-failure keeps prior + latches needsResync. Existing
  `Typed*DecoderTests` stay green unchanged (they test the decoders, which are
  re-fed the merged set).

### R3-S4 — Android: carry rev+state on the envelope; generated ProjectionCache; rev-aware apply
**Crate:** `android/app`. Codegen: `nmp-codegen` (Kotlin cache generator).
- Add `projectionRev: ULong` + `state: UByte` to `TypedProjectionEnvelope`
  (KernelUpdateFrameDecoder.kt); populate from `projection.projectionRev` /
  `projection.state` (Rung-2 binding exposes them).
- Generate `ProjectionCache.kt` (same algorithm). `decodeProjections` runs over
  the merged envelope set. `KernelModel.decodeUpdate` resets the cache on
  session/epoch change; the existing `decoded.rev <= _state.value.rev` guard is
  kept (frame-level monotonic).
- **Gate (`./gradlew :app:testDebugUnitTest` scoped, or the existing
  `Typed*DecoderTest` suite):** mirror the iOS cache tests; existing decoder tests
  stay green.

### R3-S5 — Capstone: S6 before/after measurement (the pass/fail gate)
**Crate:** `nmp-testing` (ffi-stress).
- The S6 harness (`s6_single_projection_churn.rs`) already measures
  `waste_ratio` via the Rung-0 churn counters. Add a second measurement *with
  incremental apply enabled* on the kernel (call
  `nmp_app_declare_incremental_apply` before the window) and compare. The

- Add a **frame-bytes** before/after: the callback already records

- **Gate:** S6 prints `waste_ratio_incremental` and asserts it `< 0.05` (a real
  PASS/FAIL, unlike Rung 0's measurement-only mode) when incremental is enabled;

## 6. The gallery typed-frame bridge

The gallery Android/iOS shells no longer carry a curated generic transport subset
or read `SnapshotFrame.payload`. Both shells call the Rust `nmp-app-gallery`
helper with the production `UpdateFrame` bytes; Rust decodes the typed
`SnapshotEnvelope` plus the sidecars Gallery renders (`resolved_profiles`,
`claimed_events`, `accounts`, `relay_role_options`, `claimed_event_embeds`, and
`signer_state` when present), then returns the existing Gallery JSON model.

**Implication:** Gallery stays a thin shell and does not need a native
FlatBuffers projection registry. The typed decode logic lives with the Rust
application crate that owns the Gallery presentation model, and the update
transport remains typed-only. Rung-3 omission still does not create a separate
Gallery cache: the helper reconstructs the full JSON model from the typed frame it
receives, while the main Chirp hosts own the incremental apply caches described in
§3.

## 7. Codex review — what changed

Two `codex exec` passes (gpt-5.5, xhigh). Verdict: **"row omission plus generated
merge cache is the right Rung 3 shape, but only if treated as a protocol-versioned
incremental mode."** Changes folded in:

1. **(Q1) Omit the row, gate it on host rev-aware support.** Adopted as D3-2 —
   `nmp_app_declare_incremental_apply()` is the per-instance capability gate; the
   kernel emits full rows until a host advertises it. Reframed (per NMP
   hard-break policy) as durable architecture, not a migration shim.
2. **(Q2) Decode-before-commit + sticky `needsResync` is the sufficient self-healing
   floor; no per-frame manifest in Rung 3.** This is the biggest simplification vs
   the parent ADR's implied manifest-gap detector. Adopted as D3-4; the four
   enabling invariants are now explicit acceptance criteria. The manifest-gap
   detector and the resync FFI are correctly deferred to Rung 4.
3. **(Q2) First-frame-must-be-baseline + `baselined` gate + `session_id==0` ⇒ no
   incremental contract.** Adopted as D3-5.
4. **(Q3) Generated raw-bytes cache-merge re-feeding existing decoders over a
   Tantalus per-field delta updater for the first iteration.** Adopted as D3-3;
   Tantalus deferred (it layers on top later, no wire change).
5. **(Q4) Tier-1 always-Changed is a valid boundary; the metric must be labeled
   Tier-2 churn, not whole-frame waste.** Adopted as D3-7 + the S6 report wording.
6. **(Q5 / Q3) Cheap guards against a wrong-Unchanged classification:** the Rung-1
   biconditional oracle is extended to the omission case (omitted ⟺ cache-unit
   unchanged) as a test/test-support gate; the S6 capstone adds an
   incremental-vs-full byte-identity oracle. A production periodic baseline is
   explicitly rejected (no in-process loss to recover from; it would re-introduce
   O(total) cost).
7. **(Q3 buffer reuse) Safe after `to_vec`; the one trap (no retained
   pointer/slice into the builder past callback return) is documented as D3-6.**
