# Incremental Emission

## Source-Version Stamps & Rev Derivation

ADR-0055 (Rung 1) uses source-version-stamp derived revs (option c) rather than per-projection mutation-site bumps (option a) or emit-time content hashing as the default (option b). The kernel maintains ~12 per-source-table u64 version counters on a typed SourceVersions struct, each bumped at centralized write chokepoints via a single stamping &mut accessor (the Bevy Mut<T> pattern), so a new write path cannot bypass a bump and a new projection reader must declare its dependencies. Each projection's rev is derived as a SUM (saturating_add) of its declared dependency list of source counters (not MAX) — any single dependency bump advances the combined rev, ensuring strict monotonicity when two deps converge to the same value. Compute is O(1) at read with no payload touch. Epoch bumps on account-switch (set_accounts/set_active_account when the active account actually changes) and resets to 0 on kernel Reset (which rebuilds the whole Kernel struct, resetting all counters for free), providing the Rung-3 session/epoch re-baseline for host cache invalidation. The manifest enumerates the full 18-key universe (KERNEL_BUILTIN_PROJECTION_KEYS) every tick (not just present rows), so a manifest-Cleared key is visible to the omit-unchanged consumer even when the typed vector has no entry for that key. The ProjectionManifest carries session_id (= TimingMilestones::started_unix_ms) and epoch fields that reset for free on Reset (full kernel rebuild), providing the Rung-2/3 epoch and session re-baseline mechanism. The source unit for rev derivation is every input the projection accessor can observe, not just a DB table, using a typed counter struct (SourceVersions) of named u64s for Tier-2 inputs plus a const per-key declared-dependency list. Rung 2 adds tail-appended FlatBuffers fields (projection_rev, state as ProjectionPresenceState enum, snapshot_epoch, session_id) to TypedProjection and SnapshotFrame with backward-safe defaults (no reorder/renumber/delete); these are additive and backward-compatible, with Changed=0 as the default enum value. The Rung-2 encoder populates projection_rev, state, and snapshot_epoch from the manifest at emit time, not leaving them as default zeros. Host-registered keys default to rev 0 / Changed. relay_diagnostics depends on a deliberately broad diagnostics_inputs_ver bumped at the write chokepoint of every input the accessor observes (sub-fork A: one broad stamp, chosen over sub-fork B per-input stamps for simplicity and fewer chokepoints to get wrong). relay_diagnostics rev is derived from a per-emit fingerprint of its own encoded bytes (reconcile_diagnostics_fingerprint), a deliberate single-projection bounded localized exception to the no-content-hash rule that is correct by construction and effectively free because relay_diagnostics is narrowed out by default (host-declared projections) so most apps hash a single constant byte. relay_diagnostics is byte-stable across ticks when no relay event occurs, achieved by anchoring the wall clock once at kernel start (TimingMilestones::started_unix_ms) and removing all live-clock reads (SystemTime/Instant/now) from the production projection path, with zero live SystemTime/Instant reads in the projection builder. The claimed_events projection depends on claimed_event_content_ver (bumped on claim/release of events, on store-accepted events matching a live claim via narrow gate, and on profile metadata changes for authors of currently-claimed events — not on the global events_ver firehose), to avoid churning on every firehose event. Addressable first-arrival events that return InsertOutcome (not Replaced) apply the coord-key fallback on both Inserted and Replaced arms to correctly bump claimed_event_content_ver. action_lifecycle content changes from wall-clock TTL expiry (prune_expired) are treated as an explicit state transition that bumps the lifecycle stamp only when a row actually crosses its deadline (prune_expired returns whether it removed anything; bump only on real removal), not on every idle tick. ack_action_stage bumps settlement_enqueue_ver so that partial-ack content changes legitimately advance the rev and the StaleStamp oracle stays sharp. HashMap is reserved for future dynamic Tier-1 keys (out of Rung-1 scope); a typed counter struct is used for Tier-2. Tier-1 host-registered projections (claimed_event_embeds, nip46_onboarding, nmp.feed.home) have no manifest entry and are structurally un-synthesizable by the omit transform — they default to Changed and are always kept when incremental is enabled unless they opt into their own byte-equality omit.

## Biconditional Completeness Oracle

The biconditional completeness oracle runs on every emit in cfg(any(test, feature="test-support")) builds and panics on a violation. It asserts (rev_advanced || presence_changed) ⟺ cache_unit_changed for every Tier-2 key per emit, hashing the exact cache unit (key ⊕ payload, deliberately excluding rev/presence to avoid false-positive Changed→Unchanged sequences with identical payload) after the single production encode, making a missed stamp a test failure. It catches missed source-version bumps by failing a scenario test, and catches spurious bumps, verified to bite by reverting F1 and watching S1 fail. The oracle runs on the full pre-omit typed set, so omission cannot blind it. It is cfg-gated to test/test-support builds, imposing zero production cost on the emit path.

## Projection Emission Policies

Projection presence is modeled as a three-valued enum (Changed/Cleared/Unchanged) from Rung 1 onward. Steady-state keyed projections are Changed when rev advanced, Unchanged otherwise, and never Cleared while the kernel holds the state. When incremental_apply is enabled, the producer omits entire Unchanged projection rows from the wire frame (not empty payloads), keeps an explicit payload-less Cleared marker for drain/TTL projections, and sends full Changed rows — the omission gate is per-instance via nmp_app_declare_incremental_apply. Drain projections (action_results, signed_events) follow a tristate Changed/Cleared/Unchanged: Changed when non-empty, Cleared exactly once on the non-empty→empty transition, Unchanged while stably empty; note_drain_emit parks pending_presence only on this edge, not on every tick, and stably-empty ticks do not bump settlement_drain_ver, eliminating idle drain churn. They advance their revision on every non-empty emit and exactly once on the non-empty→empty Cleared transition. Copy-with-TTL projections (action_stages, action_lifecycle) use a note_copy_emit edge machine (the analog of note_drain_emit) that parks pending_presence=Cleared only on the non-empty→empty edge (the ack-of-last-entry), leaving steady-state non-empty to the rev-vs-last-emit rule, preventing perpetual Changed re-emission for stable in-flight entries. note_copy_emit ensures a genuinely-unchanged tick resolves to Unchanged and is omitted. Their prune_expired returns whether it removed anything so that rev advances only on real expiry, not on every idle tick. ack_action_stage bumps settlement_enqueue_ver so that a partial-ack content change legitimately advances the rev, keeping the StaleStamp oracle sharp without relying on the perpetual-Changed override. Rung 1 covers Tier-2 kernel-owned built-in projections only; Tier-1 host-registered typed closures remain ungated with a named follow-up (Rung 3b), and the manifest uses a typed SourceVersions counter struct for Tier-2 with HashMap reserved for future dynamic Tier-1 work. ProjectionPresence::Cleared is constructed and emitted on the non-empty→empty transition; idle drain ticks on stably-empty projections are Unchanged with no revision bump. A key emitted at rev 0 correctly settles to Unchanged after its first baseline emit; there is no perpetual byte leak. R3's .equatable() boundary on the timeline List prevents body re-evaluation on idle ticks; with R6-S1 ON, the feed key is absent from changedKeys so typedHomeFeed is not re-assigned, and the List keeps its identity — omission stops the idle re-render.

## R3-S1 Omit-Unchanged & Cleared Synthesis

Rung 1's manifest enumerates the full 18-key KERNEL_BUILTIN_PROJECTION_KEYS universe every tick (not just rows present in the typed vector); omit_unchanged iterates typed rows for present keys and then synthesizes from manifest.states for absent-but-Cleared/conditional-Changed keys. The changed_since_last_emit function treats a key absent from the last_emitted map as Changed (not Unchanged) because all SourceVersions counters start at 0, making compute_rev return 0 for most keys; without this fix, rev-0 keys would be wrongly omitted on the first frame. This deviation can only ever cause over-emission (an extra full row on the baseline frame) and never under-emission (a lost row), because revs are monotonic SUMs with no subtraction, no wrap, and no offsetting path. A key that is present in the manifest but absent from the typed vector is synthesized as a Cleared row (empty payload, WireProjectionState::Cleared) exactly once on the non-empty→empty edge, then settles to Unchanged. The omit_unchanged inverse pass synthesizes a payload-less Cleared row for manifest-Cleared keys absent from the typed vector, fires exactly once per clear edge, and uses a narrowed predicate: Cleared always synthesizes, Changed-and-absent synthesizes for the four conditional keys (action_results, signed_events, action_stages, action_lifecycle), any other Changed-but-absent triggers debug_assert+warn and never synthesizes. It also synthesizes a Changed-and-absent belt for the four conditional keys; any other Changed-but-absent Tier-2 key triggers a hard debug_assert+warn so producer bugs are not masked. Synthesis fires exactly once because record_emitted advances last_emitted for all manifest keys including the Cleared one. The R3-S1b review caught a perpetual-Changed byte leak in note_copy_emit where the non-empty arm parked pending_presence=Changed, overriding the rev-vs-last-emit rule and defeating steady-state omission; the fix parks pending_presence only on the Cleared edge (non-empty→empty), leaving steady-state non-empty to the rev-vs-last-emit rule so unchanged ticks resolve to Unchanged and are omitted. The regression test rung3_cleared_signal_tests.rs genuinely fails on master (all four conditional-key assertions) and passes on the PR head — proving it is a real correctness gate, not vacuous. No backward-compatibility shims or migration paths are maintained; when a capability changes, all implementors are hard-updated (e.g., declare_incremental_apply became a Result/i32 return across all three implementors).

## R3-S2 FlatBuffer Builder Reuse

R3-S2 reuses a single FlatBufferBuilder held on the Kernel struct across ticks (reset at the start of each encode, to_vec before return), killing per-tick allocation; bytes are copied out via to_vec() before the next tick's reset, so no use-after-reset aliasing exists. The kernel FlatBufferBuilder field is !Send (via PhantomData<*const ()> on Kernel), so no two threads can hold it; within a single make_update call the &mut borrow is exclusive and there is no re-entrant callback that could alias the builder, making use-after-reset structurally impossible.

## R3-S3 Host-Side Merge & Apply

The ProjectionCache interposer on both iOS and Android runs before the existing typed decoders, re-feeding them a merged full-envelope set so app code (KernelModel) never touches delta mechanics directly. The Rung-3 ProjectionCache makes app developers structurally unable to get incremental-apply wrong — on both platforms, app code calls the same per-key accessors and never touches delta mechanics, because the generated cache-merge layer re-feeds existing decoders a merged full envelope set. The iOS ProjectionCache is a generated codegen-produced layer that keeps a key→(rev, bytes) cache, merges each frame (Changed overwrites, Cleared drops, omitted retained), and hands the existing decoders a fully-reconstituted envelope set. On iOS, session_id and snapshot_epoch are threaded out of the single existing FlatBuffers decode pass (KernelUpdateFrameDecoder .snapshot case becomes a 6-tuple), eliminating a per-tick O(buffer) double-parse that was the cause of the original build break. iOS runs decode-before-commit: for a Changed row, the typed decoder runs as a preflight; cache advancement and changedKeys insertion happen only on success; on decode failure, needsResync latches true and the prior entry is untouched, so no decode failure blanks a value or advances rev. Android's decodeSucceeds uses bytes.isNotEmpty() as the commit-preflight; this is semantically equivalent to iOS's per-key decoder switch because FlatBuffers getRoot is unchecked and non-empty corrupt payloads pass on both platforms, so the real fail-closed path is the re-decode-from-merged-set where typed decoders use try/catch with identifier checks. Android's KernelModel re-decodes from the merged envelope set (not the raw frame), so omitted projections keep their prior value — the finding-4 regression (blanking omitted slots) is avoided on both platforms. The Android ProjectionMergeCache is semantically identical to the iOS twin in rebaseline atomicity, reorder guard, Cleared handling, session-zero pass-through, and changedKeys precision. On both iOS and Android, a session/epoch change atomically clears the cache and resets baselined/needsResync before the row loop, ensuring rebaseline is atomic and no stale entries survive across sessions. Session ID and snapshot epoch are read from the single decode on both platforms (no second buffer re-parse). The host-side apply layer (KernelModel) guards each projection-keyed @Published slot with changedKeys.contains(...) (the apply-only-changedKeys fix), so omitted slots retain their prior value without being starved — frame-level slots (typedEnvelope, flatFeeds, lastErrorToast) remain always-updated and ungated. ADR-0055 R3-S3 decrees no per-frame manifest in Rung 3 because the kernel→host channel is synchronous in-process with no in-transit loss, so decode-before-commit plus a sticky needsResync latch is a sufficient self-healing floor.

## FFI & Incremental Apply Gate

Incremental emission is gated by a per-instance capability flag nmp_app_declare_incremental_apply, which returns an i32 error code (0=ok, 1=AlreadyStarted, 2=RegistryUnavailable, -1=null app) rather than using debug_assert, making the capability gate fail-safe. It is a single-writer, set-before-start gate (debug_assert on !started), idempotent, and fails safe to false/no-rows on poison or no-slot. It is called after declare_consumed_projections but before nmp_app_start, gated on !started — a repeat declare before start is idempotent and returns 0; non-advertising hosts get byte-identical Rung-2 behavior with full rows every tick. When incremental_apply is disabled (capability OFF), should_emit always returns Some (always emits), making the path byte-identical to pre-Rung-3 behavior. declare_consumed_projections at the nmp-defaults builder is compile-time enforced via the ProjectionsDeclared typestate; .start() is only callable after .declare_consumed_projections(keys) or .consume_all_builtin_projections(); projection-declaration omission is a compile error with two compile_fail doctests proving it. The bidirectional drift gate every_codegen_decoded_builtin_is_declared intersects SNAPSHOT_PROJECTIONS with KERNEL_BUILTIN_PROJECTION_KEYS and asserts all are in CHIRP_CONSUMED_BUILTIN_PROJECTIONS, preventing declared-set drift from the codegen registry: every declared key must be a kernel builtin (direction-1 drift is caught by the gate), and every codegen-decoded builtin must be declared, with two documented non-codegen exceptions. The gallery app's curated minimal nmp/transport Kotlin subset must not be blanket-regenerated; only the full android/app/src/main/java/nmp/ package gets the standard regen. The ADR-0055 ladder scope explicitly excludes Tier-1 host-registered typed projections from gating this rung (D3-7); they remain always-Changed, with Tier-1 feed gating deferred to a future rung. SnapshotRegistry::incremental_apply_enabled is a single Arc<AtomicBool> shared between the producer and kernel (set-before-start, single-writer), eliminating the two-flags-for-one-fact smell and the lib.rs file-size expansion. Each sub-step of the ADR-0055 ladder is opus-reviewed before landing, and any blocker found in review must be fixed before merge; agents do not self-merge PRs.

## Rung-0 Baseline Waste Measurement

Rung 0 measured 81.2% projection-serialization waste under single-projection-churn steady-state (1600 serialized, 300 changed, 1300 wasted bytes), validated by independent reproduction, anchoring the architectural decision for per-key gating rather than row-deltas. ADR-0055 records all four design forks as DECIDED: (1) one global snapshot_epoch, (2) wire state is 2-valued Changed/Cleared with omission=Unchanged, (3) session_id reuses started_unix_ms, (4) row-deltas deferred to measurement. The incremental-emission ADR is renumbered to 0055 (0053=host-declared projections, 0054=web-persistence), with no stale references to the old number. The S6 capstone measured Phase A (incremental OFF) at 81.2% Tier-2 serialization waste and Phase B (incremental ON) at ~18% frame-byte reduction (9640→7928 B) and 68.8% Tier-2 row suppression (1600→500 rows) with zero data loss (byte-identity verified end-state, not per-tick). The S6 capstone uses row_suppression_ratio (≥0.50, measured 0.6875) as the headline gate instead of waste_ratio (<0.05) because two always-Changed Tier-1 projections (claimed_event_embeds, nip46_onboarding) dominate the hash-waste metric and Tier-1 gating is a later rung. The S6 capstone byte-identity oracle is fail-closed: only claimed_event_embeds and nip46_onboarding may be absent without triggering a hard failure; any other dropped key or payload mismatch hard-fails the capstone. The S6 harness module docstring honestly states ~18% byte reduction and 68.8% Tier-2 row suppression with zero data loss, not the earlier false ~81%→<5% claim. The serialize_us timing gate uses a 20% tolerance band (p50_a × 1.20) to accommodate inherent cross-instance OS scheduling noise, and the timer scope captures the omit-pass and Cleared-synthesis CPU cost; Phase B is consistently faster than Phase A across all runs, confirming no hidden CPU regression. Rung 3 Tier-2 omission does not gate Tier-1 host-registered projections (claimed_event_embeds, nip46_onboarding), which remain always-Changed by design; the larger remaining byte savings live in a deferred Tier-1/feed-gating rung. The Rung-0 instrumentation (EmitProjectionStats, measure_emit_churn, per-key hash store) is fully cfg(any(test, feature = "test-support"))-gated; production builds have zero hashing/cloning/field-writes on the emit path, verified at the binary level (nm shows 0 instrumentation symbols). The home feed re-serializes a byte-identical ~58.8 KB payload on every idle 4 Hz tick (~6× the rest of the frame), with release encode at ~129 µs and debug at ~2,266 µs (17.6× factor); approximately 6× the rest of the frame, with no change-signal in the engine today. Because the feed is host-registered (not a kernel built-in) and its state lives outside the kernel, kernel manifest gating is architecturally wrong; the omit must happen in the producer closure via Ok(None). The feed change-signal uses exact byte-equality (full memcmp of the retained Vec<u8>), not a hash, because a hash collision on this surface would freeze the timeline permanently; the ~58.8KB buffer is trivial to retain. The op_feed engine's snapshot() method remains untouched by all R6 changes; the emission decision lives entirely in the producer-closure layer. When incremental_apply is OFF (capability not declared), should_emit always returns Some regardless of byte comparison, making the capability-OFF path byte-identical to pre-Rung-6 behavior; the feed is emitted every tick regardless of content equality. The feed producer rebaselines on FrameIdentity(session_id, snapshot_epoch) — the same two-axis signal the host ProjectionCache resets on — so ActorCommand::Reset cannot freeze the feed by clearing the host cache while the producer still holds stale last_emitted bytes; the bespoke account-switch emission_epoch is deleted as subsumed. Kernel::publish_frame_identity runs at the top of make_update (before run_typed_projections), so every projection closure reads this tick's real session/epoch values, never a stale (0,0) from before start. The kernel publishes (session_id, snapshot_epoch) each tick at the top of make_update (before any projection closure runs) via Arc<AtomicU64> handles in SnapshotRegistry, so the producer closure reads them lock-free. On ActorCommand::Reset, the same Arc<Mutex<SnapshotRegistry>> (holding the frame-identity atomics) is moved onto the rebuilt kernel via take/set_snapshot_projection_handle_for_reset, so the surviving feed closure and the new kernel share the same atomics — no dead handle, no re-freeze. The incremental_apply capability flag is a single Arc<AtomicBool> read identically by both the producer closure and the kernel; there is no duplicate mirror field that could diverge. R6-S2 generalized TypedProjectionEmissionState into nmp-core, with nmp-nip01's FeedEmissionState as a thin type alias — all 27 original S1 emission tests pass unchanged through the alias, with zero semantic drift. Both gated keys (claimed_event_embeds, nip46_onboarding) have per-key freeze-guard tests that drive byte-identical-payload-after-identity-change and assert MUST-emit. The two always-Changed Tier-1 keys (claimed_event_embeds, nip46_onboarding) are now gated on exact byte-equality via TypedProjectionEmissionState, eliminating the ~40% residual hash-waste identified in the R3-S5 capstone. Release encode cost for the feed is ~129µs at 4Hz (~516µs/s), which is negligible compared to the 58.8 KB/tick idle waste eliminated by gating. R6-S4 measures a 97.6% idle total-frame-byte reduction (45,440 B → 1,104 B) when the op_feed projection is registered and byte-equality omit is enabled. The S7 false-resend gate uses a followed-author reply to a root the engine never holds (passes predicate, reaches engine, mutates internal state, but leaves snapshot byte-identical) to genuinely exercise the byte-equality gate as the suppressor. Option B (feed row-deltas) is not warranted: it does nothing for the idle case (already fixed by omission), and on a mutating frame the List must re-render anyway because a card genuinely changed; new events are human-paced, not 4Hz. The R6-S5 analysis concluded that R3's .equatable() List boundary was already the dominant idle-jank lever (short-circuiting the expensive timeline re-render before R6 existed), and that the felt jank was on a Debug build (~17.6× slower encode than Release), so the incremental A/B should be measured on a Release device.
