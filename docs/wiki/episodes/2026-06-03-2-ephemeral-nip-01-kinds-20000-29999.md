# Episode: Ephemeral NIP-01 kinds 20000–29999 misclassified as replaceable

## Prior State

is_parameterized_replaceable included the 20000..30000 range, causing is_replaceable(20000) to return true. NIP-01 classifies kinds 20000–29999 as ephemeral (never stored). The sibling unit test encoded the wrong model and passed.

## Trigger

Master CI failure: assertion `!is_replaceable(20000)` panics in nmp-nostr-lmdb replaceable_freshness tests. Discovered during PR review sweep.

## Decision

Initially fixed by hand-correcting ranges in nmp-nostr-lmdb (PR #915), then closed #915 in favor of PR #899 which delegates to rust-nostr's Kind::is_replaceable/is_addressable as the single source of truth rather than hand-rolling NIP-01 range checks.

## Consequences

- PR #899 merged with the delegation approach; #915 closed as superseded
- nmp-nostr-lmdb now uses rust-nostr's Kind methods instead of maintaining its own range constants
- A latent identical bug exists in nmp-core/src/kinds.rs (its own is_parameterized_replaceable still includes 20000..30000), protected by green tests asserting the wrong model — flagged for follow-up

## Open Tail

- nmp-core/src/kinds.rs has the same wrong 20000..30000 range — needs a separate fix
- The green tests in nmp-core that lock in the wrong model need to be updated alongside the range fix
