# Episode: Known-signers catalog becomes Rust sole-source with codegen-enforced native lists

## Prior State

Known-signer lists were triple-vendored hand-maintained native copies (Swift×2, Kotlin×3) plus AndroidManifest <queries> and iOS plist schemes — already drifted across platforms with missing/incorrect entries (e.g. Amber/"Nostr Connect"/nostrconnect absent).

## Trigger

#1493 audit P4 and P9 flagged known-signers drift; user directed agents to fix with codex design review, specifying that hardcoded relays and pubkeys belong ONLY in app-level code, not NMP itself.

## Decision

Rust is now the sole source of truth for the known-signers catalog (nmp-signer-catalog + derive macro). Native lists are generated by `nmp gen signer-catalog` codegen (Kotlin×3, Swift×2, AndroidManifest <queries>, iOS plist schemes). A codegen-drift CI gate enforces parity — if native lists drift from the Rust catalog, CI fails.

## Consequences

- Native signers can never drift from the Rust catalog again
- Adding a new signer requires only a Rust-side change; codegen propagates to all platforms
- The hand-parse parity gate from PR2a was retired in favor of the codegen gate in PR2b
- PR was phased (2a: catalog+gate → 2b: codegen) for reviewability and collision avoidance
