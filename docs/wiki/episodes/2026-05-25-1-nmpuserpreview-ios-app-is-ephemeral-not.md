# Episode: NmpUserPreview iOS app is ephemeral — not tracked in repo

## Prior State

Swift registry screenshots were assumed to come from Xcode #Preview macros embedded directly in the SwiftUI component source files; the iOS component gallery app (NmpGallery) had been deleted as obsolete (commit 995cc4ed) with no tracked replacement

## Trigger

User corrected the assistant's assumption by pointing out the NmpUserPreview app is installed on an iOS simulator; investigation traced the app's source to /tmp/NmpUserPreview/ — a standalone Xcode project wrapping NmpUserPreviewPackage (SPM) that was generated by an agent for screenshot capture

## Decision

NmpUserPreview is the active iOS preview/screenshot vehicle, but it lives exclusively in /tmp (ephemeral) and is not version-controlled; the assistant offered to move it into the repo (e.g. ios/NmpUserPreview/) but no decision was recorded in this session

## Consequences

- The preview app will be lost on system restart since /tmp is cleared
- The registry's Swift screenshot pipeline is not reproducible from the repo alone
- NmpGallery (the prior gallery app) was intentionally deleted as obsolete with zero live FFI and no CI coverage — NmpUserPreview replaces it for user-profile previews but has the same vulnerability of being outside version control
- Kotlin/Android user-profile screenshots remain pending (gallery app not yet updated)

## Open Tail

- Should NmpUserPreview be moved into the repo under ios/NmpUserPreview/?
- Should the app be generated deterministically by nmp-cli rather than hand-maintained?
- Kotlin user-profile component screenshots still need the Android gallery app to be updated
